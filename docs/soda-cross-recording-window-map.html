3. The missing layer in the recording-4-only map

Entry and availability

Activities hub, invitation, tutorial and start/defer controls are different states. V7 at 1480s also shows activities with future-start labels. A card being present does not mean it is playable.

Progress and collection

Mission grids, event standings, bear targets, cake slices and pearl boards require different window families. Counters changing are usually state variants, not new destinations.

Ending and recovery

V5's out-of-fuel message, V7's cake closure and treasure extension prompt are not interchangeable. Separate expiration, reward collection and an offer to continue.

4. Modelling decisions

Interpretation: use a shared core loop with a mode context (numbered / mastery / cake), plus independent event branches. Represent a window as family + mode + lifecycle state. An altered tooltip, objective, reward amount or counter should normally remain a variant unless it changes the available actions.

Interpretation: treat post-level feedback as a possible sequence of overlays, not a direct guaranteed return to the map. Collection screens may update several systems, but which level types contribute to which events still needs counter-before/counter-after and continuous-action review.

Commercial observations: the sheets show offers priced in real currency, gold-bar continuation options and free reward prompts. These are separate categories; a displayed price or a later resumed board does not by itself prove a purchase, a currency deduction or a completed transaction.

Still unknown: the actual new-content arrival and portal-exit journey, universal event eligibility, all failure/retry paths, purchase completion, and the complete action edges. Level 20000 is a visible milestone, not proof of the content cap.
